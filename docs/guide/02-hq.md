# Guide: `hq/` — the HQ server

**What it is:** the central server in India. It stores the master copy of everything, receives changes from station tablets, serves the HQ dashboard, runs forecasts, and pushes updates back to stations.
**Tech:** Python 3.11+, FastAPI, Postgres (TimescaleDB image) in Docker — or a local SQLite file when `DATABASE_URL` is not set (used by tests and quick local runs).
**Full endpoint list:** [../API.md](../API.md), or open http://localhost:8000/docs while it runs.

## Folder map

| File | What's in it | Size |
|---|---|---|
| `app/main.py` | **All HTTP endpoints**, the auth gate middleware, the change log, and the background watchdog. Big file — use Ctrl+F on the URL path. | ~1700 lines |
| `app/sync_apply.py` | `apply_frame`: the **one** function that applies a change coming from a tablet | small |
| `app/dtn.py` | Unpacks a DTN bundle and passes it to `apply_frame` | small |
| `app/db.py` | Connecting to Postgres/SQLite, applying `shared/sql/schema.sql`, seeding first-boot data, the audit hash chain (`write_audit`). SQLite path from `HQ_DB_PATH` | ~350 lines |
| `app/auth.py` | JWT sign/verify, `has_role`, `require_role(...)` | small |
| `app/config.py` | Station PINs (`STATION_PINS_JSON`), allowed indent transitions, secret key, token lifetime, and the `POLARIS_ENV=production` boot guard | small |
| `app/forecast.py` | Fuel forecast = physics formula + small ML correction (ONNX model from `ai/`) | small |
| `app/snn_forecast.py` | Alternative "spiking neural network" forecast (numpy) | small |
| `app/telemetry_poller.py` | Every 15 min: fetches weather (Open-Meteo, or IMD with a key) and stores it as telemetry | medium |
| `app/vessel_poller.py` | Every 15 min: ship positions from AIS, or a scripted schedule when there's no key | medium |
| `app/_vc.py` | Vector-clock compare/merge (who has the newer change) | tiny |
| `tests/` | pytest suite. Runs on SQLite, no Docker needed | |

At the top of the file: app start-up (`lifespan` starts the pollers and a 60-second watchdog that flags overdue sorties and slow emergency triage), `notify_gateway()` + `_log_change()`, middleware (the auth gate `_auth_gate`, security headers, logging), and small helpers `_fetch_all()`, `_fetch_one()`, `_actor()` (imports `q()` and `write_audit()` from `db.py`).

## Postgres vs SQLite

The same code runs on both, through one shared path everywhere: `with _sync_txn() as cur: cur.execute(q(sql), params)`. `_sync_txn()` (in `main.py`, mirrored by `db.py`'s schema/seed helpers) opens one transaction and commits or rolls back regardless of dialect; `q(sql)` (in `db.py`) converts `?` placeholders to Postgres `%s`. No endpoint branches on `USE_PG` directly anymore — the only two places that still do are `_fetch_all()` (the SELECT cursor API genuinely differs) and `_sync_txn()` itself.

## How a tablet's change is applied (`sync_apply.py`)

1. Check the entity and operation are allowed (unknown → HTTP 400).
2. Insert the frame's ULID into `dedupe`. If it was already there → answer `DEDUPED` and stop. This makes resends harmless.
3. **Assets:** a stock movement with `delta` is added (no "who wins" — both tablets' consumption counts). A plain quantity update compares vector clocks; if HQ's copy is newer answer `APPLIED_LOCAL_WINS`, otherwise set the new quantity. Negative quantity → `CONFLICT_CRITICAL`. Either way HQ's resulting row is pushed back to the station.
4. **Everything else** (indents, personnel, sorties, emergencies, expeditions, legs, manifests, lots): update **only the fields present** in the change. Create the row if it doesn't exist and the required fields are there. A lot change with `delta` is added, like assets. Indent status must follow DRAFT → APPROVED → DISPATCHED → RECEIVED.
5. Write an audit row. If other tablets at the station should know (people, sorties, emergencies, stock), push it to the gateway.

To support a new synced entity: add it to `ENTITIES` in `sync_apply.py` (writable columns, columns needed to create, defaults) and add a test in `tests/test_sync_correctness.py`.

## Who can call what

Login (`POST /auth/login`) checks the station PIN from `config.py` and returns a JWT. Role order: `NCPOR_ADMIN` > `HQ_LOGISTICS` > `DISPATCH` = `STATION_LEAD` > `FIELD_OP` > `VIEWER`. Elevated roles are only granted to certain device-id prefixes or an admin PIN.

**The auth gate** (`_auth_gate` in `main.py`) runs before every route: every write needs a JWT (machine paths `/sync/*`, `/dtn/*`, `/telemetry` may use `X-PSK` instead), each path has a minimum role (`_ROLE_RULES`), and `/personnel`, `/audit`, `/overrides`, `/sync/changes` reads need a token. Use `_actor(fallback)` whenever you write an audit row or a `created_by`: it returns the token's identity, never the request body's. The full table is in [../API.md](../API.md#auth-gate-every-route).

Adding a write endpoint: if FIELD_OP is enough, do nothing; otherwise add a `(method, path prefix, role)` line to `_ROLE_RULES`, and a case to `tests/test_auth_gate.py`.

**Still open:** tokens are not station-scoped (a Bharati login can write Maitri rows), and logins are per station PIN, not per person.

## Talking to the gateway

`notify_gateway(station_id, entity, id, op, patch)` in `main.py` first appends the change to the `change_log` table (getting a monotonic `seq`), then sends it to the gateway, which pushes it to tablets at that station. The push is fire-and-forget: if the gateway is down it logs a warning and carries on — tablets that missed it get it later from `GET /sync/changes`, which the gateway calls when they reconnect. In Docker the gateway address comes from `GATEWAY_INTERNAL_URL`.

Always use `notify_gateway()` for anything a tablet should see; a direct POST to the gateway would skip the log and be lost to offline tablets.

## Things that confuse people

- **Two seed sources.** HQ seeds from `shared/seed.json`; the tablet from `shared/src/seed.ts`. Keep ids in sync.
- **`init_db()` never crashes the app.** If the database isn't ready, `/health` still answers so Docker doesn't restart-loop; check the logs.
- **Forecast inputs can be assumed.** With no weather reading, `/forecast` uses nominal weather and marks it `tele.source = "assumed_default"`. The confidence range is a fixed ±15% (`ci_source: placeholder_15pct`), not a real model interval.
- **`used_model`** in the forecast response is `true`/`false` (whether the ML correction ran), not a model name.
- **Production mode is opt-in.** `POLARIS_ENV=production` makes HQ refuse to start on the demo `SECRET_KEY`/`PSK_HEX`/PINs. Without it (plain `docker compose up`), demo secrets work and only log warnings.
- **Auto-indents don't stack.** One open auto-indent per asset and station; a 60-day watch draft is upgraded to CRITICAL in place when the forecast worsens.

## Run locally

```bash
pip install -r hq/requirements.txt -r hq/requirements-test.txt
```

```bash
python -m uvicorn hq.app.main:app --port 8000
```

Without `DATABASE_URL` it creates `hq/app/hq.db` (SQLite, ignored by git; `HQ_DB_PATH` picks another file). Run tests **from the repo root** (some tests read `docker-compose.yml`):

```bash
python -m pytest hq/tests -q
```

`hq/tests/conftest.py` gives every pytest run a fresh temp SQLite file (the dev `hq.db` is never touched) and gives every `TestClient` an admin token by default. To test as an anonymous caller use `TestClient(app, headers={"Authorization": ""})`.

Lint (same as CI; config in `ruff.toml`):

```bash
ruff check .
```
